# Design decisions and changes from the proposal

Recorded as they were made. All decisions used the dev split only; the test splits were first evaluated after all of them (see results/TEST_LOG.md timestamps).

- 2026-11-13: R1 (reproduction check): Table-R1 reports no HybridQA/MultiHiertt numbers (L1); our Tier-S models are not comparable to published HybridQA systems. R1 becomes "report published numbers for context, not a reproduction target".
- 2026-11-13: Environment is macOS/MPS: Makefile uses `.venv/bin/python`; `make paper` uses pdflatex+bibtex (latexmk absent).
- 2026-11-23: R2 (candidate features). First real H1 run (seed 0, pre-R2 policy) reached dev EM 0.058 (dev-subset EM fell 0.113 -> 0.053 during training). Diagnostics on 300 dev questions (scratchpad scripts, dev only, test untouched): behaviour cloning on gold paths reached only ~0.20 hop-0 accuracy, even on train, below BM25-argmax 0.264. Cause: the gold anchor is lexical, and the policy saw only embeddings while B3 already received cos/bm25 scalars. Fix, applied identically to H1, A1-A4, B2a and B2b (policy) and to B3 (scorer): per-candidate features [cos, bm25_norm, question-token overlap, header overlap] (`CandidateGen.features`, `Policy.feat_*`). With R2, BC reaches hop-0 accuracy 0.40 and path validity 0.29. All pre-R2 RL runs (h1 s0 20261123-041027, b2a s0) are superseded and excluded from results.
- 2026-11-23: R3 (row evidence). Answer-head input renders each selected cell as its whole row and each selected passage as text; passages are seen only when the policy selects them (`render_evidence(mode="row")`, `results/answer_head_row`, configs/answer_head_row.yaml). Oracle M0 is unchanged in practice (dev EM 0.603 vs 0.610 with entity mode). H1 seed 0 (R2) dev EM 0.083 with entity mode vs 0.114 with row mode. Applied to every path method (rl_base, b3_soft, m0). Non-learned reference (300 dev): top hop-0 cell + its row's linked passages = EM 0.253. Further reward or HP changes go only through T16 with equal trials per method.
- 2026-11-24: R4 (tuning budget). T16 uses 3 trials per trained method (spec default 6), fixed grid, dev seed 0: RL methods {default, lr 1e-3, entropy 0.03}; B3 lr {1e-3, 3e-4, 3e-3}; B1 lr {3e-4, 1e-4, 1e-3}. Ablations inherit H1's choice. Reward weights stay as pre-registered (spec 02). Driver: scripts/run_study.py, state in results/study/state.json.
